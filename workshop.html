🎯 Why Containerize Legacy Apps?

🚀 Benefits

  • Consistency - Same environment everywhere
  • Isolation - No more "works on my machine"
  • Portability - Run anywhere (dev, staging, prod)
  • Scalability - Easy to scale horizontally
  • Fast Deployment - Seconds instead of hours
  • Resource Efficiency - More apps per server

⚠️ Challenges

  • Stateful Data - Databases need special handling
  • Configuration - Environment variables
  • Networking - Inter-container communication
  • Legacy Code - May have hidden dependencies
  • Security - New security considerations
  • Monitoring - Different logging approach

🔍 Step 1: Assess Your Application

Questions to Answer

  • What type of app? - Frontend, Backend, Full-stack, Database
  • What runtime? - Node.js, Python, Java, .NET, etc.
  • What databases? - SQL Server, MySQL, PostgreSQL, MongoDB
  • What external services? - APIs, FTP, Email, etc.
  • What environment variables? - Configuration needs
  • What ports? - Which ports does the app use?
  • Native dependencies? - C++ libraries, system tools
💡 Tip: Check package.json, requirements.txt, or pom.xml for dependencies

📝 Step 3: Create Dockerfile

Basic Dockerfile Structure

# 1. Base Image
FROM node:18-alpine

# 2. Working Directory
WORKDIR /app

# 3. Copy package files
COPY package*.json ./

# 4. Install dependencies
RUN npm install

# 5. Copy source code
COPY . .

# 6. Build (if needed)
RUN npm run build

# 7. Expose port
EXPOSE 3000

# 8. Start command
CMD ["npm", "start"]

📝 Step 3: Backend Dockerfile (AdonisJS)

FROM node:18-alpine

WORKDIR /app

# Install system dependencies for native modules
RUN apk add --no-cache \
    python3 \
    make \
    g++ \
    curl \
    curl-dev \
    libtool \
    openssl-dev

COPY package*.json ./
RUN npm install

COPY . .

# Build the application
RUN node ace build --ignore-ts-errors --production

# Create non-root user for security
RUN addgroup -g 1001 -S nodejs
RUN adduser -S adonisjs -u 1001
RUN chown -R adonisjs:nodejs /app
USER adonisjs

EXPOSE 2239

CMD ["npm", "start"]

📝 Step 3: Frontend Dockerfile (Vue.js)

# Build stage
FROM node:18-alpine AS build-stage

WORKDIR /app

COPY package*.json ./
RUN npm install

# Copy env file (Vite embeds at build time)
COPY .env.development .env

COPY . .
RUN npm run build

# Production stage
FROM nginx:alpine AS production-stage

COPY nginx.conf /etc/nginx/nginx.conf
COPY --from=build-stage /app/dist /usr/share/nginx/html

USER root

EXPOSE 7101

CMD ["nginx", "-g", "daemon off;"]

🔨 Step 4 & 5: Build & Test

Build Image

# Build the image
docker build -t my-app .

# With custom tag
docker build -t my-app:v1.0.0 .

# With build args
docker build \
  --build-arg NODE_ENV=prod \
  -t my-app .

Run Container

# Basic run
docker run -d \
  --name my-app \
  -p 3000:3000 \
  my-app

# With env file
docker run -d \
  -p 3000:3000 \
  -v $(pwd)/.env:/app/.env:ro \
  my-app

# With volume for development
docker run -d \
  -p 3000:3000 \
  -v $(pwd):/app \
  -v /app/node_modules \
  my-app

⚠️ Common Issues & Solutions

Issue 1: npm ci fails

Problem: package.json and package-lock.json not in sync

Solution: Use npm install instead of npm ci

Issue 2: Native module build fails

Problem: Missing build tools (python, make, g++)

Solution: Install system dependencies in Dockerfile

Issue 3: TypeScript errors

Problem: Build fails due to TS errors

Solution: Use --ignore-ts-errors flag or skipLibCheck

Issue 4: Env variables not working

Problem: Vite/React embeds env at build time

Solution: Copy .env file before build or rebuild image
