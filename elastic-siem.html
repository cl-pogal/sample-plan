01 AWS Marketplace Setup Approach
Deployment Method — Elastic Cloud via AWS Marketplace (Recommended)
01
Subscribe via AWS Marketplace
Navigate to AWS Marketplace → search "Elastic Cloud" → select the Elastic Cloud (Elasticsearch Service) listing → click Subscribe. This links the Elastic Cloud subscription directly to the IAS AWS billing account — no separate Elastic invoice.
AWS Marketplace · PAYG
02
Create Elastic Cloud Organisation
After subscribing, Elastic redirects to cloud.elastic.co to create an organisation linked to the AWS account. The billing flows through AWS Marketplace consolidated billing — Elastic usage appears as a single line item on the AWS bill alongside EC2, S3, and other services.
Elastic Cloud Console
03
Deploy Elastic Stack Cluster
Within the Elastic Cloud console, create a new deployment: select AWS as the cloud provider → choose region (Singapore ap-southeast-1 as the nearest supported region; Jakarta ap-southeast-3 is not yet listed in Elastic Cloud). Select Elastic Security as the solution template → configure hot/warm tiers and Kibana size.
Solution Template: Elastic Security Region: ap-southeast-1 (nearest to Jakarta)
04
Configure Fleet Server & Data Ingestion
Fleet Server (managed by Elastic Cloud) handles all Elastic Agent registrations. Agents are deployed to endpoints and on-prem servers via policy-based enrollment. AWS log sources are connected via the Elastic AWS integration (S3 + SQS pull model). Network devices are routed through a syslog forwarder running on a lightweight EC2 instance in Jakarta.
Fleet Server · Elastic Agent S3 · SQS · EC2 Forwarder
05
Enable SIEM, UEBA, and Detection Rules
Activate the Elastic SIEM app in Kibana, enable ML-based anomaly detection jobs for UEBA, and import the pre-built detection rule library (800+ MITRE ATT&CK-mapped rules). Configure alert connectors for email, Slack, and ticketing system notifications. Set up role-based access for SOC analyst tiers.
Platinum Tier — all features included

05 Scope of Works
✓ In-Scope
Elastic Cloud deployment via AWS Marketplace — cluster provisioning, hot/warm tier configuration, Kibana setup, Fleet Server activation
AWS log source integration — CloudTrail, VPC Flow Logs, WAF Logs, GuardDuty findings, Security Hub findings via S3+SQS connector
Elastic Agent deployment on 100 endpoints — Windows, macOS, Linux; EDR policy configuration; enrollment via Fleet Server
Network device syslog integration (10 devices) — EC2 syslog forwarder setup, Logstash pipeline, CEF parsing for provided vendors
On-prem server agent deployment (20 servers) — Elastic Agent installation, Windows Event Log and Linux syslog collection policies
SaaS integration — M365, Okta (if in use), in-house app log ingestion via REST API / Logs Ingestion API
Detection rule configuration — enable and tune pre-built rules, map to IAS environment, set initial thresholds, MITRE coverage review
UEBA and ML job configuration — anomaly detection models per user, host, and network entity
Dashboards and reporting — SOC operations dashboard, executive summary dashboard, scheduled report setup
Alert and notification setup — email, Slack, and ticketing system connectors; severity-based routing rules
RBAC configuration — SOC L1, L2, and management read-only roles
System testing and UAT — end-to-end data flow validation, alert trigger testing, analyst workflow walkthrough
Knowledge transfer and documentation — SOC runbook, admin guide, handover sessions for IAS team
✗ Out-of-Scope
SOC managed operations — ongoing 24/7 alert monitoring, triage, and incident response after handover (available as separate managed service engagement)
Network device configuration changes — enabling syslog output on firewalls/routers is IAS/vendor responsibility; Xtremax only configures the receiver side
EDR active response actions — endpoint isolation, process kill, malware quarantine are policy configurations handled by IAS security team post-handover
Custom SOAR playbook development — automated response orchestration via external SOAR platform (can be added as a Phase 2 scope)
Compliance auditing and certification — Xtremax configures the technical controls; formal PCI DSS, ISO 27001, or SOC 2 audit readiness assessment is separate
In-house application code changes — if IAS apps require code modifications to emit structured logs, this is performed by IAS development team
Third-party SaaS connectors not listed in scope — e.g. Google Workspace, GitHub, Salesforce (only in-scope if explicitly listed and API access is provided)
Physical network access to on-prem servers — Xtremax performs remote agent installation; physical rack access or network patching is IAS responsibility
Procurement and licensing negotiation — Elastic AWS Marketplace subscription is set up by IAS using their AWS account; Xtremax provides guidance only
Threat intelligence feed integration — paid TI feeds (Recorded Future, CrowdStrike TI, etc.) are not included; only Elastic's built-in TI is configured
Post-go-live rule tuning beyond UAT — fine-tuning based on operational feedback after formal handover is a separate retainer scope
06 Implementation Assumptions
A01
IAS has an active AWS account with sufficient IAM permissions (Administrator or Security Admin) to create IAM roles, S3 buckets, SQS queues, and EC2 instances in Jakarta region.
A02
IAS will subscribe to Elastic Cloud on AWS Marketplace using their own AWS billing account. Xtremax provides guidance but does not purchase or hold the Elastic Cloud subscription on IAS's behalf.
A03
Elastic Cloud does not currently support ap-southeast-3 (Jakarta). The Elastic cluster will be deployed in ap-southeast-1 (Singapore). IAS legal and compliance team to confirm this is acceptable for data residency requirements.
A04
CloudTrail organisation trail is already enabled and logging to an S3 bucket. If not, this will be set up within the project scope but may require additional time.
A05
IAS IT team provides remote access (SSH, RDP, or endpoint management platform) to all 100 endpoints and 20 on-prem servers for Elastic Agent installation. Agent deployment via GPO or Ansible is preferred for Windows environments.
A06
All 10 network devices support Syslog or CEF output. IAS IT team or network vendor enables syslog forwarding to the Xtremax-configured EC2 syslog forwarder IP. Firewall rules allowing UDP/TCP 514 from devices to forwarder are IAS responsibility.
A07
IAS provides API credentials or service accounts for SaaS integrations (M365 Global Reader role, Okta API token, etc.). Credentials are handled securely and not stored outside the Elastic Cloud keystore.
A08
A dedicated IAS project coordinator and technical point of contact (IT/security team) is assigned for the duration of the project and available for daily standups during active implementation weeks.
A09
Log volume is approximately 5 GB/day across all sources. If actual volume significantly exceeds this (e.g. above 10 GB/day), the Elastic Cloud cluster sizing may need to be upgraded, impacting monthly cost.
A10
IAS existing ticketing system (Jira or ServiceNow) has an API available for Kibana alert connector integration. Credentials and webhook URLs will be provided by IAS during the alerting configuration phase.
A11
On-premises servers have outbound internet access (port 443) to Elastic Cloud endpoints in Singapore for agent telemetry. If isolated networks require a proxy, IAS provides proxy credentials and Xtremax configures agent proxy settings.
A12
The project operates in English and Bahasa Indonesia. All deliverable documents (runbook, admin guide, architecture diagrams) will be produced in English unless IAS explicitly requests Bahasa Indonesia versions.
